# Инструкция домашнему агенту

Работайте только с каталогами и настройками, которые указал владелец. Все
переменные и пути берите из локального `.env`; не записывайте реальные пути,
домены, IP, пароли или токены в Git.

## Сначала опрос, потом установка

Не начинайте с `cp .env.example .env`, `mkdir`, `chown`, `make up` или
перемещения музыки. Сначала выполните только безопасные проверки, которые не
меняют систему: ОС, `docker --version`, `docker compose version`, `id` текущего
пользователя и занятость предполагаемого порта. Не обходите домашние каталоги,
не открывайте аудиофайлы и не делайте выводов о назначении папок только по их
названиям. После того как владелец назовёт целевые пути, проверяйте свободное
место только на этих разделах.

После этих проверок отправьте владельцу один собранный опрос. Не спрашивайте то,
что можно безопасно обнаружить самому; укажите UID/GID текущей оболочки как
обнаруженное значение, а не как уже выбранный аккаунт, и предложите значения по
умолчанию:

1. **Каталог проекта:** куда клонировать код? Предложите отдельный каталог кода,
   не смешанный с музыкой и базой.
2. **Каталог музыки:** какой путь назначить MUSIC_ROOT? Внутри него Compose ожидает permanent/, cache/ и incoming/. Какая существующая музыка должна считаться постоянной, какая временной, и куда агент может положить только те файлы, которые владелец сам разрешил импортировать? incoming не виден Navidrome и cleaner-у. Не переносите, не объединяйте и не переименовывайте существующие каталоги; если структура иная, предложите план и ждите решения.
3. **Данные Navidrome:** какой путь назначить `NAVIDROME_DATA`? Это новая пустая
   база или уже существующая установка? Для существующих данных уточните
   резервную копию и разрешение использовать именно этот каталог.
4. **Пользователь и права:** подходит ли обнаруженный числовой PUID:PGID? Navidrome читает permanent/cache и пишет NAVIDROME_DATA; cleaner пишет только cache; importer читает incoming и записывает только новые файлы в permanent после отдельного подтверждения. Не запускайте рекурсивный chown/chmod; если прав не хватает, покажите точные пути и спросите разрешение.
5. **Подключение клиентов:** нужен доступ с домашнего сервера, из домашней LAN или через уже настроенный VPN? По умолчанию 127.0.0.1 доступен только на сервере. Не открывайте публичный интернет, не меняйте firewall/роутер и не настраивайте reverse proxy без отдельного явного согласия.
6. **Очистка:** подходят ли `30` дней, `20 GiB` и минимальный возраст `60`
   минут? По умолчанию остаётся `DRY_RUN=true`; уточните, кто будет проверять
   кандидатов. Не спрашивайте разрешение на реальные удаления заранее как
   подразумеваемое согласие — для `DRY_RUN=false` понадобится отдельное
   подтверждение после просмотра фактического dry-run.
7. **Запуск:** можно ли после согласования путей создать пустые папки и локальный
   `.env`, скачать закреплённые образы и запустить контейнеры? Попросите
   подтверждение одного итогового плана перед этими изменениями.
8. **Сканирование Navidrome:** нужен ли вызов `startScan` после реального
   удаления? Если да, объясните, что владелец сам внесёт логин/пароль в локальный
   `.env`. Не просите пароль в чате, не печатайте его и не сохраняйте в Git.

9. **Разрешённые источники:** какие точные домены вы независимо проверили и хотите внести в локальный sources.json? По умолчанию список пуст. Агент не выбирает каталоги, не скачивает файлы и не считает наличие CC-метки доказательством прав. Для каждого файла владелец подтверждает источник, точную лицензию и атрибуцию.

Покажите владельцу короткий шаблон для ответов, чтобы он мог заполнить его
целиком:

```text
Каталог проекта:
MUSIC_ROOT:
  permanent: создать пустую / существующая папка (путь):
  cache: создать пустую / существующая папка (путь):
  incoming: создать пустую / существующая папка (путь):
  перемещать существующую музыку: нет / согласованный план:
NAVIDROME_DATA: новая база / существующая (путь); backup:
Пользователь, PUID:PGID: использовать найденного / другой:
Клиенты: Symfonium Android / AmpSonic или Amperfy iOS/macOS:
Доступ: хост / LAN / уже настроенный VPN:
Адрес и порт:
Политика кэша: defaults / мои значения:
startScan: не нужен / настрою секреты сам в .env:
Разрешённые домены public-domain/CC источников (точный список; по умолчанию пуст):
Подтверждаю этот план установки: да / нет
```

Если владелец не знает ответа, не подменяйте его догадкой: объясните риск и
предложите безопасное значение по умолчанию. Отсутствие ответа на вопрос о
перемещении означает «не перемещать»; отсутствие ответа о сети означает
«оставить привязку `127.0.0.1`»; отсутствие отдельного согласия означает
«оставить `DRY_RUN=true`».

## Предусловия

- Установлены Docker Engine и Docker Compose v2 (`docker compose`).
- Есть место на диске для музыки и базы Navidrome.
- Порт из `NAVIDROME_PORT` свободен на `NAVIDROME_BIND_ADDRESS`.
- Для домашней сети подготовлен доступ к устройству или reverse proxy; по
  умолчанию сервис доступен с хоста только через `127.0.0.1`.

## Установка

1. Клонируйте репозиторий и перейдите в его каталог:

   ```sh
   git clone https://github.com/Synt744/selfhosted-music.git
   cd selfhosted-music
   ```

2. Создайте локальный файл настроек:

   ```sh
   cp .env.example .env
   ```

3. Обязательно задайте в `.env`:
   - `MUSIC_ROOT` — каталог с подпапками `permanent`, `cache` и `incoming`;
   - `NAVIDROME_DATA` — каталог данных Navidrome;
   - `PUID` и `PGID` — числовые UID/GID пользователя, которому принадлежат каталоги;
   - `TZ` — часовой пояс;
   - `NAVIDROME_BIND_ADDRESS` и `NAVIDROME_PORT`, если значения по умолчанию не подходят.

   Для вызова `startScan` после удаления дополнительно задайте
   `NAVIDROME_USER` и `NAVIDROME_PASSWORD`. Они остаются только в `.env`.

4. После подтверждения владельцем создайте только согласованные отсутствующие
   папки:

   ```sh
   set -a
   . ./.env
   set +a
   mkdir -p "${MUSIC_ROOT}/permanent" "${MUSIC_ROOT}/cache" "${MUSIC_ROOT}/incoming" "${NAVIDROME_DATA}"
   ```

   Не выполняйте `chown -R` или `chmod -R`. Если выбранному UID/GID не хватает
   доступа, остановитесь, покажите владельцу точные изменения прав и получите
   разрешение.

5. Покажите владельцу итоговую таблицу `host path → container path → access`
   и сетевую привязку. После подтверждения проверьте конфигурацию и запустите
   сервисы:

   ```sh
   make config
   make up
   ```

## Чеклист после запуска

- `docker compose ps` показывает Navidrome как healthy; cleaner работает без
  ошибок и перезапусков.
- Веб-интерфейс открывается по адресу из `NAVIDROME_BIND_ADDRESS` и
  `NAVIDROME_PORT`; при первом входе создан администратор.
- Поместите один тестовый MP3 в `permanent` и один в `cache`. Оба должны
  появиться в одной библиотеке Navidrome после сканирования.
- Выполните `make dry-run`: должны отображаться только кандидаты из `cache`,
  файлы при этом остаются на месте.
- Оставьте `DRY_RUN=true`, пока владелец не проверит кандидатов и явно не
  подтвердит переключение. Не меняйте его на `false` самостоятельно.
- Только после подтверждения владельца установите `DRY_RUN=false` в локальном
  `.env` и перезапустите cleaner: `docker compose up -d --force-recreate cleaner`.

## Импорт с подтверждёнными правами

Importer не скачивает музыку, не обращается к сети и не запускается автоматически. Он получает только каталог incoming (только чтение) и permanent (запись только для добавления новых файлов). Cleaner видит только cache. Перед каждым импортом:

1. Проверьте, что источник и файл разрешены к личному использованию и лицензия указана на странице источника. Наличие CC-метки само по себе не доказывает права загрузившего.
2. Заполните sources.json точными доменами, которые владелец отдельно одобрил; не используйте wildcard. Пустой список блокирует импорт.
3. Заполните manifest.json: относительный source_path, artist, album, title, source_url, license_id, точный canonical license_url, attribution (кроме CC0) и rights_confirmed=true.
4. Запустите dry-run и покажите владельцу файл-источник, цель и лицензию. Если источник, права, путь или цель сомнительны — остановитесь.
5. Только после отдельного подтверждения владельца выполните ту же команду с --apply. Импортёр копирует файл и provenance sidecar; исходник оставляет на месте. Он откажется перезаписать файл или пройти по symlink.

Пример dry-run:

```sh
docker compose --profile ingest run --rm --no-deps ingest --manifest /incoming/manifest.json --sources /incoming/sources.json
```

Скорость не ограничивается; перед копированием проверяется, хватает ли места на размер выбранных файлов, без дополнительной квоты. Реальный импорт требует отдельного подтверждения и флага --apply. Не автоматизируйте этот флаг. Не добавляйте Prowlarr, qBittorrent, Soulseek/slskd, общие торрент-индексаторы или yt-dlp. Любой будущий законный P2P-источник требует отдельного задания и явного списка источников; Gluetun сам по себе источник прав не подтверждает.

### Если просят подключить трекер или загрузчик

Не добавляйте торрент-индексаторы, magnet-ссылки, qBittorrent/Prowlarr, Soulseek/slskd или код скачивания. Объясните: importer не скачивает и не имеет сети; конфигурация не предусматривает пиратские источники. Не описывайте, как подключить их вручную.

Для источника, который владелец независимо подтвердил как разрешённый public-domain/CC, изменяется только локальный `$MUSIC_ROOT/incoming/sources.json`: укажите точный lowercase hostname без wildcard; не коммитьте этот файл. Сам аудиофайл владелец помещает в `incoming/` вручную, а manifest обязан содержать HTTPS-страницу и поддерживаемую точную лицензию. Сначала dry-run и проверка владельцем; `--apply` — только после отдельного подтверждения. Наличие CC-метки само по себе не является доказательством прав.

## Музыкальные клиенты

### Android — Symfonium

- Тип сервера: Subsonic / Navidrome.
- URL: адрес, доступный с телефона. 127.0.0.1 работает только на самом сервере; для телефона используйте подтверждённую LAN/VPN-сеть.
- Введите логин и пароль созданного пользователя Navidrome. Секреты не присылайте в чат.
- Для MP3 настройте транскодирование в клиенте и проверьте на одном треке; оригинал на диске не менять. Не включайте `ND_ENABLETRANSCODINGCONFIG` по умолчанию: редактирование серверных профилей может позволить запуск произвольных команд. Для пользовательского профиля нужно отдельное решение владельца и отключение настройки после изменения. Navidrome предупреждает, что редактируемый профиль может запускать команды на сервере: https://www.navidrome.org/docs/usage/admin/security/#transcoding-configuration

### iPhone/iPad/Mac — AmpSonic или Amperfy

Оба клиента поддерживают Navidrome/Subsonic; проверьте минимальную версию ОС и текущую совместимость перед установкой. URL и учётная запись должны быть теми же, что для других клиентов.

## Типовые проблемы и откат

- **Порт занят:** задайте другой `NAVIDROME_PORT`; проверьте привязку
  `NAVIDROME_BIND_ADDRESS`.
- **Нет доступа к музыке или cleaner не может удалить файлы:** сверьте `PUID`,
  `PGID`, права на `MUSIC_ROOT/cache` и `NAVIDROME_DATA`. Каталог `permanent`
  cleaner не монтирует.
- **Навидром не запускается:** `docker compose logs navidrome`; проверьте
  доступность registry, healthcheck и права на каталог данных.
- **Нужно остановить:** `make down`. Это останавливает контейнеры, но не удаляет
  каталоги музыки или данные Navidrome.
- **Восстановление Navidrome:** остановите сервис (`make down`) и восстановите
  резервную копию всего `NAVIDROME_DATA` в настроенный каталог, сохранив
  владельца и права; затем выполните `make up`.

## Агенту запрещено

- Агент не меняет, не перемещает и не удаляет файлы в `permanent`. Единственное исключение — одноразовый importer, который после просмотра dry-run и отдельного подтверждения владельца может добавить только новый файл; существующие файлы и исходники не перезаписывает и не удаляет.
- Не коммитить `.env`, пароли, токены, реальные домены или IP.
- Не устанавливать `DRY_RUN=false` без подтверждения владельца.
- Не превращать importer в сетевой загрузчик и не добавлять секреты без отдельного
  задания владельца.

- Не автоматизировать скачивание из The Pirate Bay, общих публичных трекер-индексаторов, Soulseek или YouTube Music; не считать происхождение файла подтверждённым только по имени или тегам.
- Импортёр не имеет сетевого доступа, работает только по команде и по умолчанию в dry-run. Не запускать его с --apply без отдельного подтверждения на конкретный dry-run.
- Не открывать общий торрент-клиент, Prowlarr, slskd/Soularr или загрузчик YouTube в этой конфигурации.
